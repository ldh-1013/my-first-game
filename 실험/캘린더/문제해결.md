# 문제 해결 — 창은 뜨는데 화면이 비어 있을 때

설치한 컴퓨터에서 앱 창은 떴는데 안이 하얗거나 까맣게 비어 있다면, 아래 순서로 확인한다.

## 1. 오류 로그 보내기

앱이 실행은 되는 상태라면 **설정(⚙) → 오류 로그 폴더 열기**를 누른다.
탐색기가 열리면서 `render-errors.log` 파일이 선택된다. 이 파일을 그대로 보내면 된다.

앱이 아예 안 뜨거나 메뉴를 누를 수 없으면, 탐색기 주소창에 아래를 붙여넣어 같은 폴더로 간다.

```
%APPDATA%\my-calendar
```

로그에는 이런 줄이 남는다.

| 줄 | 뜻 |
| --- | --- |
| `app start version=… gpuDisabled=…` | 앱이 시작된 시각과 하드웨어 가속 상태 |
| `did-fail-load code=… desc=…` | 화면 파일 자체를 못 읽음 (설치 손상, 백신 차단 등) |
| `render-process-gone reason=…` | 화면을 그리는 프로세스가 죽음 (메모리 부족, 드라이버 충돌 등) |
| `preload-error …` | 백업·진단 다리를 놓는 단계에서 실패 |
| `child-process-gone type=GPU …` | GPU 프로세스가 죽음 → 아래 2번을 시도 |
| `renderer/error-boundary …` | 화면은 떴지만 그리는 도중 예외 (메시지와 스택이 같이 남는다) |
| `renderer/window-error …` | 리액트가 시작되기도 전에 실패 |

로그 파일은 256KB를 넘으면 앞부분을 잘라내므로 무한정 커지지 않는다.

## 2. 하드웨어 가속 끄고 실행해 보기

오래된 그래픽 드라이버, 원격 데스크톱, 가상머신에서는 GPU 가속 때문에 화면이 빈 채로
뜨는 일이 있다. 이럴 때만 끄면 된다 — 기본값은 켜짐이고, 멀쩡한 컴퓨터에서 끄면
렌더링만 느려진다.

1. 탐색기 주소창에 `%APPDATA%\my-calendar` 를 붙여넣어 폴더를 연다.
2. 그 안에 **`disable-gpu`** 라는 빈 파일을 만든다. (확장자가 붙어 `disable-gpu.txt`가 되어도 인식한다.)
3. 앱을 껐다 켠다. 로그 첫 줄이 `gpuDisabled=true`로 바뀌면 적용된 것이다.

되돌리려면 그 파일을 지우고 다시 켜면 된다.
개발 중이라면 `MYCAL_DISABLE_GPU=1` 환경변수로도 같은 효과를 낼 수 있다.

## 3. 데이터는 어디에 있나

- **일정·기분 기록**: 렌더러의 localStorage (위 `%APPDATA%\my-calendar` 폴더 안)
- **자동 백업**: `문서\나의 캘린더 백업\my-calendar-backup-YYYY-MM-DD.json` (하루 한 개, 최근 30개 보관)
- **오류 로그**: `%APPDATA%\my-calendar\render-errors.log`

백업 폴더와 로그 폴더는 서로 다른 위치이고 쓰는 코드도 따로다. 화면이 비어 보여도
백업 파일은 그대로 남아 있으니, 앱을 다시 설치한 뒤 **설정 → JSON 불러오기**로 되살릴 수 있다.

## 4. 빌드할 때 주의

설치 파일은 반드시 `npm run dist:win`으로 만든다. 이 스크립트는
`npm run build && electron-builder --win nsis`라서 화면 파일(`dist/`)을 항상 새로 만든 뒤 패키징한다.
`electron-builder`만 따로 실행하면 예전 `dist/`가 그대로 들어가, 설치한 컴퓨터에서만
낡은 화면이 뜨거나 파일을 못 찾는 일이 생길 수 있다.
